# Product Vision

## Primary Audience

The initial audience is a tabletop roleplaying group that plays through Discord, voice
chat, or a similar social channel and wants a shared visual memory of the campaign.

The DM needs help preparing, organizing, and presenting the world.

Players need help remembering places, people, factions, mysteries, and consequences.

## Core Promise

The app makes the campaign world feel persistent.

When the group returns after a week or a month, the world should not feel trapped in
old chat messages. It should feel present, browsable, and alive.

## Desired Feel

Atlas Mythos OS should feel:

- useful before it is fancy
- calm, readable, and trustworthy
- imaginative without becoming cluttered
- more like a campaign operations table than a marketing website
- friendly to both DMs and players

## First-Order Workflows

### Create Campaign

The DM creates a campaign space with:

- campaign name
- system or ruleset label
- privacy settings
- player list
- high-level world premise

### Create World Objects

The DM can create:

- regions
- settlements
- locations
- NPCs
- factions
- events
- quests or threads
- items or artifacts

### View World Graph

The group can browse relationships:

- this NPC belongs to this faction
- this faction controls this city
- this event happened in this region
- this rumor mentions this ruin
- this player discovered this clue

### View Map

The map starts simple:

- uploaded image or blank canvas
- named regions
- pins
- boundaries
- object detail drawer

The first map does not need to be beautiful. It needs to be connected to campaign data.

### Record Session Notes

The DM or group can add session notes, then AI can suggest:

- NPCs mentioned
- places mentioned
- unresolved threads
- changed relationships
- possible timeline entries

All suggestions require review.

### Separate Knowledge

Different information can be:

- public to players
- private to the DM
- hidden until discovered
- AI-suggested but unaccepted

## Campaign Framework

Campaigns should support campaign-specific presentation, curated registries or
collections, visual identity, and hierarchical maps without hard-coding a genre or ruleset.

See `docs/08-campaign-framework.md` for the conceptual boundary and future direction.

## Early Feature Boundaries

The MVP should avoid:

- tactical combat automation
- complete ruleset support
- full character sheet systems
- procedural world simulation
- multiplayer live cursors
- complex permissions
- full Discord bot integration

These can come later. The early product should prove that campaign memory plus map-linked
world objects is compelling.

## Design Direction

The interface should prioritize:

- dense but clean information
- clear navigation
- maps and object panels
- quick creation
- searchable memory
- visible status labels for canon, private, public, and suggested content

Avoid a landing-page feel inside the app. The first screen should be the usable campaign
workspace.
