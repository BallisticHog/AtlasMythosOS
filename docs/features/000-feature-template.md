# Feature Specification Template

## Identifier and Status

- Identifier: `F###`
- Status: proposed | approved | in progress | complete | superseded

## Objective

State the measurable outcome this feature should create.

## User Problem

Describe who has the problem and why the current experience is insufficient.

## User Flow

List the primary path from entry point to successful outcome.

## Scope

List included behaviors, screens, and boundaries.

## Non-Goals

List explicitly excluded work to prevent scope drift.

## Affected Modules

Name expected application areas, routes, components, services, and documentation.

## Data Implications

Describe new or changed entities, validation, visibility, canon status, and migrations. State `None` when applicable.

## UI States

Describe loading, empty, populated, selected, error, and disabled states that apply.

## Accessibility

Define keyboard, focus, semantic, contrast, and responsive requirements.

## Tests

List automated and manual checks required for the feature.

## Acceptance Criteria

Write observable, testable completion criteria.

## Risks

List implementation, data-integrity, security, or product risks.

## Completion Report

On completion, record changed files, checks run, manual testing, known limitations, and follow-up work.
